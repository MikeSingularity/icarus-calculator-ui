# ADR-002: Unified DAG Production Graph and Dynamic Shopping List

- **Status:** Implemented
- **Date:** 2026-04-06
- **Corpus/Module:** icarus-calculator-ui: src/utils/graphBuilder.ts, src/store/usePlanStore.ts

## 📋 Context

The current graph implementation uses a tree-based structure with path-based unique IDs (e.g., `axe.0_stick.0_wood`). This causes several issues:

1. **Node Duplication:** Identical items (e.g., "Stone") appear multiple times if reached via different paths, confusing the user and making it hard to see total resource requirements.
2. **Disconnected Shopping List:** The "Shopping List" is a separate UI component. Attempts to draw lines from the graph to the sidebar are brittle and frequently "break."
3. **Layout Overlap:** Complex Tier 5 items with deep dependency trees often overlap other nodes because the simple recursive layout doesn't account for the global space.

## 🎯 Decision

We will refactor the graph architecture to a Directed Acyclic Graph (DAG) with the following characteristics:

1. **Joined Nodes:** Use `itemId` as the unique `id` for all nodes. Aggregate quantities across all paths.
2. **Target-on-Left Flow:** Anchor finished products on the left. Expand dependencies to the right.
3. **Dynamic Terminal Column:** All leaf nodes (raw materials) and nodes marked as "Done" will automatically move to a dedicated "Shopping List" column on the far-right of the workspace.
4. **Native Connectivity:** Eliminate the separate `MaterialPane` and `DynamicLinker`. All connections will be native React Flow edges.

## ⚖️ Consequences

- **Positive:**
  - Eliminates duplicate nodes for the same item.
  - Guaranteed line connectivity (no more brittle SVG overlays).
  - Natural production flow from "Goals" to "Materials."
  - Improved layout stability for T5 items.
- **Negative:**
  - Marking an item as "Done" affects all paths using that item (though this is desired for a "joined" graph).
  - Requires a multi-pass graph construction logic which is slightly more complex than a simple recursion.

## 🔄 Alternatives Considered

- **Keeping the Tree structure:** Rejected because it doesn't solve the core UX complaint about duplicate resource nodes.
- **Improved Dynamic Linker (SVG):** Rejected as it addresses the symptom (brittle lines) rather than the cause (separate UI containers for same data).
